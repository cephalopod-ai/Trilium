## UP-00 — Integrate the upstream main baseline deliberately

Upstream main already contains work that older open branches try to implement: newer help infrastructure, template title defaults, and substantial AI tool-permission/approval lifecycle changes. The [template title-default commit](https://github.com/TriliumNext/Trilium/commit/948a9135144bdca5ccbf1742e951b64fb56378b5) is a concrete prerequisite for the open template-properties PR. Bringing in a branch based on recent main can transitively import hundreds of baseline commits; its small feature diff is not its total merge impact.

The upstream AI changes worth comparing explicitly include [resetting grants for a new sidebar chat](https://github.com/TriliumNext/Trilium/commit/55dbe1dd8d), [keeping Codex note reads permission-gated](https://github.com/TriliumNext/Trilium/commit/cdb316f33d), and [separating tool approvals between chats](https://github.com/TriliumNext/Trilium/commit/0a731bc6a5). Their commit ancestry is missing locally; equivalent fork behavior must be checked before deciding which changes to transplant. This is not a claim that every corresponding bug exists in this fork.

Use an isolated integration branch/worktree for the larger catch-up. Retain fork setup/auth gates and audit regression cases, reconcile commons wire types and provider factories, then bring across feature slices. Resolve source conflicts before regenerating help artifacts. Baseline catch-up and small independent fixes can proceed as separate changes; avoid bundling all 85 heads into one integration.

## Detailed opportunities

### UP-01 — Custom themes should retain automatic OS color-scheme behavior

**Recommendation: first small fix.** The branch adds a `themeBase === "next"` check before `getThemeStyle()` falls back to computed CSS. The local function handles built-in theme names but does not recognize that an arbitrarily named custom theme inherits the automatic base. A snapshot of computed dark/light CSS can therefore be treated as a fixed choice. The branch includes a focused regression test; its two-file patch applies cleanly, and the three-way check is also clean. Source: [reviewed theme-fix head](https://github.com/TriliumNext/Trilium/tree/5bbbb5da11a5).

Local evidence: `apps/client/src/services/theme.ts:3`, especially the CSS fallback after built-in theme-name handling. Validate a custom automatic-base theme, fixed-base variants, OS preference changes, and relevant embedded-editor/editor-theme consumers. No database or protocol migration is involved.

### UP-02 — Restore text-editor selection after interacting with embedded content

**Recommendation: small editor fix with focused browser validation.** The local content-embed plugin directly sets CKEditor's private renderer focus flag to false on widget interaction. The reviewed [PR #11953](https://github.com/TriliumNext/Trilium/pull/11953) restores that flag from the editing view's focus state on view `mousedown` and `keydown`, at highest priority, when ordinary editor input resumes. It adds regressions for returning to text, deleting the include and preserving link-preview behavior. The patch and three-way checks are clean.

Local evidence: `packages/ckeditor5/src/plugins/content_embed/content_embed.ts` has the focus-suppression writes, with no corresponding `restoreRendererFocus` helper. The PR description still refers to an earlier selection-range-listener approach; the fetched head uses view input listeners. Port the reviewed source and tests, not a reconstruction from the prose. Validate click-back selection, typing over a selected word, deletion, link previews, nested editable includes and keyboard interaction. The use of a private CKEditor field is a maintenance dependency.

### UP-03 — Keep a hidden tab anchored when its width changes

**Recommendation: contained usability fix.** [PR #11954](https://github.com/TriliumNext/Trilium/pull/11954) records the visible block and relative offset during scrolling, then restores it after a hidden container is shown at a different size. A pixel `scrollTop` alone cannot preserve the same text position through reflow. The local `ScrollingContainer` handles note-switch and temporary read-only scroll behavior but has no block-anchor/ResizeObserver mechanism. The patch and three-way checks are clean.

The new helper skips hidden, inline and positioned boxes, searches from the previous anchor, and checks that the anchor still belongs to the container before restoring. Listener, observer and animation-frame cleanup are included. Validate long notes with percentage-sized images, sidebar changes while the tab is hidden, window resizing, note switches, split panes and repeated disposal in a real browser. The added unit tests mock geometry; they are useful but do not establish real-layout correctness. Inspect layout-read costs on long notes before making any performance claim.

### UP-04 — Detect incomplete AI streams on the worker transport

**Recommendation: adapt the remaining gap, retaining the fork's SSE protection.** The local SSE path already tracks `done`/`error`, ignores trailing chunks after terminal completion and reports an unexpected EOF. Consequently [PR #11124](https://github.com/TriliumNext/Trilium/pull/11124), an SSE-focused fix, is largely already represented. The broader `ccr-0ffe4a49-xlaobv` branch moves terminal enforcement to the exported wrapper shared by SSE and worker messages, and changes the inline assistant's completion fallback.

Local evidence: `apps/client/src/services/llm_chat.ts:140` has SSE terminal tracking. In `streamChatOverMessages()` at line 188, an `llm-stream-end` resolves the transport and the queued chunks are awaited, but no terminal chunk is required. `apps/client/src/widgets/type_widgets/text/ai_assistant_stream.ts` still resolves on the returned stream promise, allowing partial worker results to look complete. Review source and tests in the [cross-transport branch](https://github.com/TriliumNext/Trilium/tree/01820dd18094d284688be9b359438ac8fb6ec3de); its exact SHA is in the inventory.

The net patch does not apply as-is, but a three-way simulation is clean. Preserve the native CLI/ACP/Gosling callbacks, ordered async chunk handling and abort semantics while consolidating terminal validation. Test worker end-without-done, SSE EOF, valid completion, error completion, abort, callback rejection and approval callbacks. A clean merge alone does not verify those fork-specific paths.

### UP-05 — Script modals need body-level portals and complete render disposal

**Recommendation: selective adaptation.** [PR #11877](https://github.com/TriliumNext/Trilium/pull/11877) wraps the public script Modal in a portal beside Bootstrap's body-level backdrop, carrying source-pane identity and render-note styling scope. It also unmounts old Preact roots and ignores late async results after refresh or disposal. That addresses both layering and stale body-level portal lifetime.

Local evidence: `apps/client/src/services/frontend_script_api_preact.ts` still exports the internal Modal directly. The local render service clears the container and dispatches async rendering without the proposed cancellation protocol. However, this fork's API already uses a fourth `parentComponent` argument, cached `froca.getScriptBundle()`, and `trackPendingRender()` for printing. The PR uses that argument position for an AbortSignal and an older bundle-loading path. The three-way check reports three conflicting render files.

Keep the fork API and print tracking; add cancellation in a compatible signature and preserve component context. Validate refresh/unmount while bundle execution is pending, nested script modals, pane-local links, scoped CSS, focus trapping, Escape, backdrop hit testing and printing. This is a useful lifecycle fix, not a safe file replacement.

### UP-06 — Optional archived-last sorting

**Recommendation: small opt-in feature if wanted.** [PR #11955](https://github.com/TriliumNext/Trilium/pull/11955) adds `#sortArchivedLast` on sorted parents. Archived grouping takes precedence over `#top`, `#bottom`, folder ordering and normal sort direction; those rules then apply within each group. The local builtin attribute list and tree sorter do not contain it. The patch and three-way checks are clean.

The implementation also re-sorts affected parents when an archived label changes, including inherited/template cases, and supplies core tree/handler tests. Validate truthy/false values, descending/natural sorting, cloned children, inherited archived labels, removal and sync events. Run the focused core suites under both server and standalone. The patch includes legacy generated help HTML; reconcile that representation with the chosen upstream-help baseline when integrating.

### UP-09 — Attribute multi-selection and clipboard operations

**Recommendation: useful productivity feature, medium integration effort.** Draft [PR #10797](https://github.com/TriliumNext/Trilium/pull/10797) adds selection actions and mobile affordances to the attribute UI. Its clipboard service serializes attributes using the existing parser syntax, carries relation targets rather than display titles, preserves inheritance, and merges pasted values according to single/multi-valued definitions. An internal held clipboard supports menu paste when browser clipboard access is unavailable; it intentionally can differ from the system clipboard.

The 13-file net change touches the sidebar, editor, clipboard and renderer. Check current UI architecture before adopting it. Keep backend dedupe/validation authoritative; frontend paste merging is not a substitute for the fork's attribute integrity repairs. Validate dangerous labels, quote/Unicode round trips, relation targets, repeated paste, readonly/protected notes, multi-valued duplicates, keyboard selection and touch interactions. The source's preprocessing path parses clipboard HTML through jQuery; review that boundary with malicious clipboard cases before adoption.

### UP-10 — Add map/PDF viewport context to AI without weakening privacy gates

**Recommendation: strategically relevant to this AI-focused fork, after permission integration.** The [view-context branch](https://github.com/TriliumNext/Trilium/tree/0e800e00f3ec040576a77cdcfe3e03d122350b81) adds client view-state registration, a context preview/toggle and a `viewContext` request field. Map context includes viewport/selection details with bounded lists; core frames the text as an untrusted contextual hint. The local chat/context services have no corresponding `viewContext` field at the reviewed snapshot.

The branch predates the fork's expanded native/ACP provider paths. Its ten three-way conflict paths include chat state and provider code. Adapt the context to the current request contract, permission decisions, note-context switch and provider handoff; explicitly review the branch's default-enabled context choice. Turning note access off must also stop sending its viewport-derived information, and a chat must not retain revoked context. Test missing/closed views, rapid note switches, bounding and redaction, all provider families, disabled note access and protection-session changes. Do not port old chat factories over current Gosling/native handling.

The local `apps/server/src/services/open_id.ts` has substantial issuer/routing validation but no equivalent explicit refresh coordinator. Three files conflict in the simulated merge: app wiring and the OIDC implementation/specs. Preserve setup-token/auth/session behavior and distinguish invalid-grant handling from transient issuer errors. Validate concurrent expiry, rotated token reuse, response order/cookies, logout, revocation, multiple sessions, no refresh token and temporary failures. This is authentication state work, not a routine middleware insertion.

**Recommendation: benchmark experiment.** The [utility-process spike](https://github.com/TriliumNext/Trilium/tree/516b86678adee490eeb1d69636a7d9778e883c72) moves backend work behind an environment-controlled process boundary, adds message-port/protocol plumbing and an options replica in the main process. ## Important exclusions and conditional opportunities

**Do not re-port stronger-local or exact duplicates.** The TOTP drift branch offers behavior already covered locally by `CLOCK_DRIFT_STEPS = 1`, with additional persisted replay prevention in `apps/server/src/services/totp.ts:59–120`. Retain that stronger implementation. The script-deployer typecheck and split-keyboard-shortcut tests reverse-apply cleanly and have matching patch IDs. The table self-echo fix (`feature/various_bugfixes`) and Opus model update (`pr-9496`) also have matching stable patch IDs despite later local edits. The `stable` head reverse-applies cleanly. Their graph-unmerged appearance does not justify redundant merges.

**Shared editing, multi-user isolation and relation reification need separate projects.** [PR #12044](https://github.com/TriliumNext/Trilium/pull/12044) adds guest text editing with edit-root grants, passwords/CSRF, attachments and a useful expected-version/409 save model. That concurrency pattern may inform future mutation routes, but the full feature creates new public write ingress and needs a focused auth/content/upload review. [PR #10348](https://github.com/TriliumNext/Trilium/pull/10348) explicitly defers broadcast and search filtering to a later phase; a clean upstream merge state does not make it complete tenant isolation. Draft [PR #11855](https://github.com/TriliumNext/Trilium/pull/11855) couples relation-instance notes to attribute lifecycle and graph rendering; resolve identity/delete/undo/sync semantics before relying on it.

**Flashcards are promising but data-model work.** [PR #11260](https://github.com/TriliumNext/Trilium/pull/11260) proposes FSRS scheduling, Anki round trips and two synchronized entities, with revision/idempotency fields on review requests. It is a large learning-workflow feature, not a UI-only add-on. Mixed-version sync, migrations, backup/restore and partially imported media need validation against the fork's existing data-integrity repairs. No runtime claims from its PR were independently reproduced.

**Tailnet provider support is a scoped operator feature.** [PR #11571](https://github.com/TriliumNext/Trilium/pull/11571) adds an explicit IPv4/CIDR allowlist for carrier-grade-NAT addresses on the operator-configured relaxed `fetchApi` path. Source leaves strict public fetches separate and does not allow arbitrary address ranges via this setting. This could help local AI endpoints over Tailscale. Validate exact-address/subnet matching, invalid tokens, IPv4-mapped addresses, DNS pinning, redirects and cloud metadata cases before porting; do not replace the strict fetch path with a blanket private-network allowance.
